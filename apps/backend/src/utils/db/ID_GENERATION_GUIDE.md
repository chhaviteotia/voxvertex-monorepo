# ID Generation Guide

This document explains how different types of IDs are generated in the system.

## 1. Custom String IDs (disputeId, etc.)

### Format: `DSP-{timestamp}-{random}`

**Example:** `DSP-1735123456789-A3F2`

**How it works:**
```javascript
const timestamp = Date.now();  // Current time in milliseconds
const random = Math.random().toString(36).substring(2, 6).toUpperCase();
const generatedDisputeId = `DSP-${timestamp}-${random}`;
```

**Components:**
- `DSP` - Prefix (Dispute)
- `{timestamp}` - Current time in milliseconds (ensures uniqueness)
- `{random}` - 4-character random string (base36, uppercase)

**Where it's used:**
- `disputeId` in Dispute model
- Generated in `apps/backend/src/dispute/services/dispute.service.js` (line 42-45)
- Also has a backup pre-validate hook in `apps/backend/src/dispute/models/dispute.js` (line 338-345)

**Advantages:**
- Human-readable
- Sortable by time
- Easy to identify in logs
- No database dependency

**Disadvantages:**
- Longer than ObjectId
- Requires manual generation

---

## 2. MongoDB ObjectIds (Database IDs)

### Format: 24-character hexadecimal string

**Example:** `507f1f77bcf86cd799439011`

**How it works:**
```javascript
// Direct MongoDB approach
const id = new mongoose.Types.ObjectId();

// Database-agnostic approach (recommended)
import { createId } from '../../utils/db/idUtils.js';
const id = createId();
```

**Where it's used:**
- All MongoDB document `_id` fields
- References between documents (user IDs, event IDs, etc.)
- Generated automatically by MongoDB if not provided

**Advantages:**
- Automatically generated by MongoDB
- Guaranteed unique
- Compact (24 characters)
- Contains timestamp information

**Disadvantages:**
- Not human-readable
- MongoDB-specific (but abstracted via `idUtils.js`)

## 3. Database-Agnostic ID Utility

### Location: `apps/backend/src/utils/db/idUtils.js`

**Purpose:** Abstract ID operations for easy migration from MongoDB to SQL/AWS

**Functions:**
```javascript
import { 
  isValidId,      // Check if ID is valid
  createId,       // Create new ID
  normalizeId,    // Convert string to database ID format
  idToString,     // Convert ID to string
  idsEqual,       // Compare two IDs
  normalizeIds    // Normalize array of IDs
} from '../../utils/db/idUtils.js';
```

**Current Implementation:**
- Uses MongoDB ObjectId for database IDs
- Can be swapped to SQL UUID/INT by changing `DB_TYPE` environment variable

**Example Usage:**
```javascript
// Validate an ID
if (isValidId(userId)) {
  // ID is valid
}

// Create a new ID
const newId = createId();

// Normalize (convert string to ObjectId)
const normalizedId = normalizeId(userId);

// Compare IDs
if (idsEqual(id1, id2)) {
  // IDs are equal
}
```

## 4. ID Generation Strategy by Type

### Dispute IDs
- **Type:** Custom String
- **Format:** `DSP-{timestamp}-{random}`
- **Generated:** In service layer before creating Dispute instance
- **Backup:** Pre-validate hook in model

### User IDs
- **Type:** MongoDB ObjectId
- **Format:** 24-char hex string
- **Generated:** Automatically by MongoDB
- **Access:** Via `idUtils.js` functions

### Event IDs
- **Type:** MongoDB ObjectId
- **Format:** 24-char hex string
- **Generated:** Automatically by MongoDB
- **Access:** Via `idUtils.js` functions

### Profile/Experience/Education/Award IDs
- **Type:** MongoDB ObjectId
- **Format:** 24-char hex string
- **Generated:** Using `createId()` from `idUtils.js`
- **Location:** `apps/backend/src/profile/services/profile.service.js`

## 5. Migration Considerations

### For MongoDB → SQL Migration:

**Custom String IDs (disputeId):**
- ✅ No changes needed - already database-agnostic
- Can keep same format or switch to UUID

**MongoDB ObjectIds:**
- Use `idUtils.js` functions everywhere
- Change `DB_TYPE=sql` in environment
- Update `idUtils.js` SQL provider implementation
- No code changes needed in services

**Example Migration:**
```javascript
// Before (MongoDB)
DB_TYPE=mongodb
// Uses: new mongoose.Types.ObjectId()

// After (SQL)
DB_TYPE=sql
// Uses: crypto.randomUUID() or auto-increment
```

---

## 6. Best Practices

1. **Always use `idUtils.js` for database IDs** - Makes migration easier
2. **Generate custom IDs in service layer** - Before creating model instance
3. **Use pre-validate hooks as backup** - For custom IDs
4. **Never hardcode MongoDB-specific code** - Use abstraction layer
5. **Validate IDs before using** - Use `isValidId()` function

## 7. Code Examples

### Generating Dispute ID
```javascript
// In dispute.service.js
const timestamp = Date.now();
const random = Math.random().toString(36).substring(2, 6).toUpperCase();
const generatedDisputeId = `DSP-${timestamp}-${random}`;

const dispute = new Dispute({
  disputeId: generatedDisputeId,
  // ... other fields
});
```

### Creating MongoDB ObjectId
```javascript
// Recommended (database-agnostic)
import { createId } from '../../utils/db/idUtils.js';
const newId = createId();

// Direct (MongoDB-specific - avoid if possible)
const newId = new mongoose.Types.ObjectId();
```

### Normalizing IDs
```javascript
// Convert string to ObjectId
import { normalizeId } from '../../utils/db/idUtils.js';
const eventId = normalizeId(req.body.eventId) || req.body.eventId;
```

## Summary

- **Custom IDs (disputeId):** Generated manually with timestamp + random
- **Database IDs (_id):** Generated via `idUtils.js` (MongoDB ObjectId currently)
- **Migration-ready:** All ID operations use abstraction layer
- **Best practice:** Always use `idUtils.js` functions for database IDs
